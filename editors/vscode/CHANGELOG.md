# Changelog

## Unreleased

- **Impact analysis**, computed by the compiler (`arclang impact`) and shown in its own editor tab: what a change to an element reaches across every layer (realizations, allocations, deployments, exchanges and ports, functional chains, satisfactions, verifications, hazards, ownership, types, constraints, declared diagrams and tables), each element with its distance, its shortest explanation path (`LC-BATT --satisfies--> REQ-R --verified by--> TC-R`), a category and a severity (blocker, major, minor). A **what-if** (delete, change an attribute, retype, move) is applied to a copy and compiled: the gate before and after, the constraints that flip, the latency budgets, the requirement coverage, the stale verdicts, then *Apply the change* (one undo) or *Discard*; *Impact of my changes* compares with HEAD, main or any revision. Graph by rings, table with clickable paths, filters, the impacted elements outlined on the workbench diagrams with counts on the layer tabs, Markdown / HTML / Excel change-request reports, Copy as table, Ask AI. See `docs/IMPACT.md`.
- **Import from every visible place, one flow.** An *Import* button (cloud icon) in the title bar of the ArcLang model view, and a welcome in that view when the workspace has no `.arc` file (*Import a Capella model*, *Import SysML v2*, *Import requirements (ReqIF)*, *New model*; also the API server and DOORS). In the Explorer, *Import* on `.capella`, `.melodymodeller`, `.aird` (read through the `.capella` beside it), `.sysml`, `.kerml`, `.reqif`, `.reqifz` (the ReqIF document inside is unpacked) and on a `.json` that lists SysML v2 API records; on a folder, *Import SysML v2 folder as one model* when it holds `.sysml` files and *Import Capella project* when it holds a `.capella`. Several `.sysml` files selected together are one model. In the workbench, *File ▾ › Import a model…*, and a `.capella`, `.sysml` or `.reqif` file dropped on the sheet (Shift held, VS Code's rule for a page) is offered for import.
- One quick pick of the source (Capella model, SysML v2 file(s) or folder, SysML v2 API server, ReqIF, DOORS through its ReqIF export), the target asked (a new `.arc`, or for requirements, *into the open model*: added at its end, compiled with it, as one undoable edit and left unsaved; refused with the reason if the whole would not compile), a progress that can be cancelled.
- **SysML v2 API server** (the standard Systems Modeling API): base address (https, or http on this machine; no credentials in the address, no redirect followed, never another host's page), token kept in the secret storage, then the project, the commit (newest first) and every element of it, page by page, imported as one model.
- **An import report** in a tab: what was imported and what was left out and why (the compiler's own counts), its notes, whether the written model compiles and how many error findings the check reports, or the refusal with the `.rejected.arc` the compiler kept; buttons *Open workbench*, *Open model*, *Run check*.
- **Save, in the workbench toolbar**: a *Save* button with a ● while the model has unsaved changes (and in the title of a diagram's own tab); ⌘S / Ctrl+S on the canvas saves the document through VS Code, so the canvas history (⌘Z) is untouched; a `.sysml` is written back through the SysML v2 export. With `files.autoSave` on, the button reads *Saved* and is disabled. *File ▾ › Save as…* writes SysML v2, Capella (`.capella`, `.aird`, `.afm`), ReqIF (requirements) or a copy as `.arc`, through `arclang export`, with a save dialog.
- Tests: the format detection, folder and `.aird` resolution, `.reqifz`, API paging and address rules, the report parser (`test/unit/importing.test.ts`); `test/e2e/vscode_import_test.js` in VS Code itself, AZERTY keys: a Capella model by its `.aird`, a SysML v2 folder from the Explorer, ReqIF into the open model, an API import against `arclang serve`, a drop, then ● / ⌘S / the file written / ⌘Z kept / Save as SysML v2 read back / auto save.
- **Arrange as in draw.io** (zorder): *Bring to front* ⇧⌘F, *Send to back* ⇧⌘B, *Bring forward* ⌥⇧⌘F and *Send backward* ⌥⇧⌘B (one step past the nearest box it overlaps, among the boxes of its container; children stay above their container; a multi-selection keeps its order), in the context menu (*Order*), the floating toolbar (⧉) and Layout ▾; kept as `order` in `<model>.layout.json`, drawn the same after a reload, one ⌘Z each.
- **Layers made of tags** (⇧⌘L, or the Layers button of the toolbar): Default (what carries no tag) and one layer per tag, the first tag of an element being its layer, with counts. An eye hides a layer (its boxes and their lines are neither drawn nor exported: SVG, PNG, Copy as image, PowerPoint; the export menu says so); a padlock locks it (no move, resize, reconnection, delete or rename on the canvas, the properties stay editable); rows dragged or moved with ▲ ▼ draw a layer above the others; *Move the selection to a layer* sets the tag through `arclang edit` (the first tag replaced, the others kept, one undo); *New layer…*. Kept in the layout file (`layers`).
- **Groups**: ⌘G groups sibling boxes in a frame (refused, with the reason, across containers), ⇧⌘G ungroups, *Remove from group*; a group moves, aligns and stacks as one, nests, has an optional label, collapses to one box (its lines end on its border); a double-click edits inside, Esc leaves. Kept in the layout file (`groups`); the model is not changed. *Group into a new component…* (or function, node, state, where the method lets one hold the others) creates the container through `arclang edit` and moves the selection into it, one edit, one undo.
- **Lock** an element (⌘L): a padlock on it, the same refusals as a locked layer (`locked` in the layout file). **Same size / width / height** as the last selected box. **Clear waypoints** of the selected lines (or of the lines of the selected boxes). **Select boxes** ⇧⌘I, **Select lines** ⇧⌘E, **Select none** ⇧⌘A. All in the `?` list. VS Code keybindings under the canvas's when-clause (so ⇧⌘F there is not Find in Files), resolved on the keyboard's layout, AZERTY included.
- Tests: the stacking, layers, groups and the transform of the drawing (`tools/diagram_render/layers.test.mjs`), the layout file's new sections, bounds and pruning (`tests/diagram_layout_file.rs`), the edits and keys (`test/unit/arrange.test.ts`), the browser (`test/e2e/arrange_test.js`) and VS Code itself with AZERTY keys (`test/e2e/vscode_layers_test.js`).
- **A click on the diagram no longer drives the text.** A single click only selects (the properties, the tree and the other tabs follow); it never opens, replaces or focuses an editor and never moves the text's cursor or scroll. With the text on screen the declaration is highlighted (`arclang.workbench.followSelection`: `highlight` by default, or `off`). A **double-click** goes to the source (`arclang.workbench.doubleClick`: `source` by default, or `rename` for draw.io's in-place rename; F2 and the menu always rename; *Go to source* is always in the menu). The text opens **beside** the workbench in an editor group of its own, never over its tab, for the double-click, the *Source* button, *Go to source*, the tree, the tables and *Go to an element…*: one helper for every path.
- **New and Open.** *New model…* (blank, Arcadia skeleton, or an example), *New layer…* (the levels and sections the model lacks, written through `arclang edit`, one undo; a new level is an empty tab with its palette), *New diagram…* (view kind, starting elements, name; opens as a tab), *Open a diagram…* by layer with *Open in new tab*, *Open model…*. In the command palette, a *New* menu in the model tree's title bar, a welcome view when the tree is empty, a *New* menu in the workbench tool row and *Diagrams…* in the layer bar.

- **Live tables and matrices**, computed by the compiler on every change of the model (debounced), each in its own editor tab that sits beside a diagram and moves into a new window: *Requirement coverage* (text, satisfied by, verified by with each test case's computed verdict, the gate's blockers, a status per row), *Traceability matrix*, *Allocation matrix* (functions x components or nodes), *N² interfaces*, *ICD* (one row per exchange: ends, ports, items, protocol, bandwidth, latency) and *Elements* (any kind, columns picked among its attributes). Open them from the model tree (declared tables sit under their layer), *ArcLang: Open a table of the model*, *ArcLang: New table…* or *Requirement coverage table*.
- A filter bar (words, `column:text`, `column=text`, `column!=text`, `is:gap`, `-term`), a filter per column, scope and row type, *Only gaps*; sortable columns, sticky headers, rows drawn only where the view is (thousands scroll smoothly); a health bar and the gate badge in the header.
- Cells link to elements (a click shows them in the source and in the open diagram, a double-click opens the diagram); text, priority, protocol and other attributes are edited in the cell through `arclang edit`, checked by the compiler, one ⌘Z; in a matrix a click on an empty cell creates a trace of the chosen kind, a click on a filled one removes it after asking.
- Export CSV and Excel (`.xlsx`, written by the compiler), Copy (TSV and an HTML table: a table when pasted into Excel, PowerPoint or Word), *Save as table…* adds the `table` declaration to the model. Dark, light and high-contrast themes.

## 4.5.0

- **One history for the model and the arrangement**, as in draw.io: ⌘Z / ⌘⇧Z (⌘Y; Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z elsewhere) on the canvas undo and redo moves, resizes, alignments, nudges and bends as well as model edits, in the order they were made; redo never brings back an older step. Real VS Code keybindings for the canvas (undo, redo, clipboard, select all, delete, zoom: ⌘= ⌘− zoom the sheet, ⌘0 and Shift+1 fit), so they work on every keyboard layout, AZERTY included.
- **Clipboard like draw.io**: paste where you point (*Paste here*) or beside the original; several elements pasted together keep the exchanges and traces between them; a cut pasted on the empty sheet moves the element to its layer; the ArcLang source of the selection goes to the system clipboard, so a copy pastes into another model's workbench (fresh ids) and ArcLang text copied from an editor pastes onto the canvas. ⌘+drag (Ctrl+drag elsewhere) copies a box where it is dropped, as in draw.io (Alt+drag moves it off the grid); dragging one of several selected boxes moves them all, one undo.
- **Arrows that attach**: dragging an end snaps to a port within reach, else to the box under the pointer or near it (its outline marked, a port made when the exchange needs one); arrows between boxes float on the facing sides; after a manual move, exchanges are re-routed orthogonally around the other boxes, through their bends (*Reset layout* gives back the automatic routes). Edge styles orthogonal, straight or curved; a port slides along its box's border or is dropped on another box to move there; an exchange's label can be dragged; eight resize handles; a 10-unit grid with smart guides (Alt for free placement). All kept in `<model>.layout.json`.
- *New diagram from the selection*; the drawing follows the dark and high-contrast themes (exports stay light); in a narrow panel the properties float over the canvas; the box under the pointer is outlined.
- **Ask AI on a selection, as in Cursor.** Select boxes or lines in the workbench (or lines of the `.arc` text) and press **⌘I** (Ctrl+I), the **✦** of the floating toolbar or *Ask AI…* in the context menu: a prompt opens by the selection with quick actions (Explain, Fix the findings, Complete, Refine, Check against requirements). The AI gets the selection's source, relationships, neighbours, findings, metamodel and gate state, and answers with `arclang edit` requests that the compiler runs on a copy (its refusals go back to the AI) before you see anything. The preview shows the explanation, the edits, the diff of the source, the changed boxes marked on the diagram and the findings the change would add; **Apply** is one undoable edit, **Open diff** uses VS Code's diff view, **Refine…** asks a follow-up, **Reject** drops it. In the text editor: ⌘I, the light bulb (and *Fix with ArcLang AI* on a diagnostic), the context menu, or *ArcLang: Ask AI about the selection*.
- **Impact-driven suggestions.** A **✦ AI** tab beside Properties and Relations shows what an edit broke (removed traces, requirements no longer satisfied, new findings, new gate blockers) with `arclang impact` on the changed elements; the AI proposes one to three architecture changes, each with its rationale and what it resolves, each compiled before it is shown, to preview, apply or dismiss. `arclang.ai.suggestOnEdit`: `onRequest` (default: the consequences are shown, the AI on a click), `afterEachEdit`, `off`. *Analyse impact with AI* on any selection. Debounced, stale analyses cancelled, never in the way of editing.
- **Choose the AI in the settings**: `arclang.ai.provider` = `vscode-lm` (default, any model VS Code offers, Copilot included), `anthropic` (`claude-opus-5-5` by default), `openai`, `azure-openai`, `mistral`, `google`, `ollama` (local), `openai-compatible` (any base URL), or `off`; `model`, `endpoint`, `azureDeployment`, `apiVersion`, `maxTokens`, `temperature`, `timeoutSeconds`, `contextScope`, `confirmBeforeSending`. Keys in the secret storage (*Set AI API key*, *Clear AI API key*), *Test AI connection*, *Configure AI* from the status bar item that names the provider and the model.
- One provider layer over `fetch`, no SDK: streamed answers and native tool calling for every provider, timeouts, cancellation, keys removed from every error and log. `@arclang` and `/agent` run on the configured provider (unchanged with `vscode-lm`).
- Safety: an AI's answer is data (only edit requests of known shapes are taken, all through the compiler, none applied without Apply); the first request to a cloud provider is confirmed; the **ArcLang AI** output lists each request (provider, model, endpoint, size; never a key); the provider, endpoint and consent are user settings only.
- Tests: the providers against a local fake server speaking the OpenAI, Anthropic, Gemini and Ollama wire formats (streaming, tool calls, headers, redaction, timeout, cancellation; `test/ai/fake-llm-server.js`); the context, answers, requests, diff and consequences against the real compiler; `test/e2e/vscode_ai_test.js` in VS Code itself with the fake server as an OpenAI-compatible provider: ⌘I on two boxes, a monitoring component proposed, previewed, applied, compiled and undone with ⌘Z; a text-selection ask; a suggestion after an edit that breaks a trace, applied (28 checks).

## 4.4.0

- **Change what is already drawn**, draw.io style but on the model, every change checked by the compiler and one undo:
  - **Reconnect** an exchange by dragging an end of the selected line to another box or port (valid targets highlighted, port directions kept, a port made where it lands on a box), or with *Reconnect the source/target…*: component and functional exchanges, interactions, physical links, transitions, scenario messages; a trace is retargeted from the Relations view, its rationale kept.
  - **Reverse** an exchange (floating toolbar, menu, properties); its ports turn around with it when they carry nothing else.
  - **Rename in place** by double-click, on boxes and on the label of an exchange or message; F2 as before. A double-click no longer jumps to the source (*Go to source* is in the menu).
  - **Move to…** for any element, ports included: a port takes the ends of its exchanges with it.
  - **Copy, cut, paste, duplicate** (⌘C ⌘X ⌘V ⌘D): paste goes into the selected box, cut then paste is a move, ids made unique (`LC-X` becomes `LC-X-2`).
  - **Align** (left, centre, right, top, middle, bottom) and **distribute** a selection; **smart guides** while moving or resizing (Alt moves freely); **arrow keys** move the selection by 1, Shift by 10; **band selection** by dragging on the empty sheet (Space+drag pans); **bend** an exchange by its middle, a double-click on a bend removes it. All kept in `<model>.layout.json`.
  - **Quick connect**: an arrow on each side of the box under the pointer; dragged it connects, clicked it creates a connected element of the same kind.
  - **A context menu** on boxes, ports, exchanges, selections and the sheet, in place of VS Code's; **a floating toolbar** by the selection; **`?`** lists the shortcuts.
  - The properties of an exchange show its ends and its attributes (protocol, bandwidth, data type…), editable.
- Needs a compiler built from this repository after 4.3.0 (with an older one these gestures are refused with "unknown variant"): `arclang edit` learns `reconnect` (refused when a port goes the wrong way, an exchange would join an element to itself, or the compiler warns about the result) and `duplicate`; a rename falls back to a relationship of that name; a move of a port rewrites its exchanges; the layout file keeps bent exchanges (`edges` with `points`).
- Edits from the workbench run one after the other, each on the text the previous one left (two quick gestures both land), and are written only onto the text they were computed from.
- `test/e2e/editing_test.js`: 43 checks of these gestures against the real compiler; `vscode_real_test.js` reconnects, opens the menu, aligns and duplicates twice in a row in VS Code itself (20 checks).

## 4.3.0

- **The workbench** (ArcLang: Open the workbench): the compiler's diagram viewer beside the source with a palette (create actors, functions, components, nodes, ports; connect them by interactions, functional and component exchanges, physical links), a properties view typed by the metamodel, a semantic browser, the findings and the gate. Every gesture is an `arclang edit` request: refused unless the edited model compiles, applied as one undoable change in the editor. Text and views edit the same file; the selection follows from one to the other.
- **The model tree** in the ArcLang side bar: the elements of the active model by layer and ownership, with Go to source, Rename, Delete and Ask @arclang.
- **The agent**: `@arclang /agent` changes the open model step by step through the compiler; tools `arclang_model` (elements, ids, relationships, findings) and `arclang_edit` (a list of edits applied as one undoable change, refused as a whole if the model would not compile) for agent mode, the chat participant and other assistants.
- **SysML v2 files** open in the same workbench and tree: imported by the compiler for the views, written back through the SysML v2 export after an edit (ids kept, layout of the original not kept). Syntax colouring for `.sysml`.
- Palette for modes and states (states, modes, transitions with a guard) and for scenarios (messages between lifelines); the cursor follows into the views for `.sysml` files too.
- Requires the compiler 4.3 (`arclang workbench`, `arclang edit`).
