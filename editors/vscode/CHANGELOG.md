# Changelog

## Unreleased

- Fixed in `arclang prove`: the proof is compiled for the widths of the board (an `int` of 16 or 32 bits, a `long` of 32, so `millis()` counts on 32 bits) with fixed-width types of its own. It took them from the C library of the computer that runs the proof: with `int: 16` the proof did not compile on x86_64 (the job was red on main), and on arm64 it compiled with a `uint32_t` of 16 bits, so the machine proven was not exactly the model's. The sizes are now checked where the proof is compiled. The time in a state is compared on 64 bits.
- **`arclang recover <sketch> --propose`: an AI proposes the model of code written by hand, the proof decides.** `--with "<command>"` names the proposer: any command that reads a prompt on its input and prints its answer (an AI's command line, local or not; `ARCLANG_PROPOSER` otherwise). It is given the sketch and how a model and a `correspondence` are written, and answers with both. The answer is compiled and proven as `arclang prove` does. Refuted, the lines that do not hold and a case that shows it (the inputs, and each line's two sides before and after the step) go back to the proposer, for `--turns` answers (4 by default). The model is written only once proven, with the command that replays its proof with no AI; otherwise the command fails and writes nothing. ArcLang depends on no AI: the sketch goes to the command you name and nowhere else.
- **The compiler reads a correspondence.** `arclang check` (and every command that compiles the model) refuses a correspondence that names a machine, a state or a variable the model does not have, a read that is not an input, or a line that does not say what it is in the model. Whether the correspondence holds stays the proof's to say.
- **A refuted `arclang prove` shows a case.** Under the lines that do not hold: the inputs of the step, and for each line the value of the code's side and of the model's side before and after, those that differ marked.
- Fixed in `arclang prove`: the machine now steps at the period of the correspondence (a time of 500 ms with a `loop()` of 20 ms is 25 steps; it was counted with the model's default period, and a right model was refuted); a question the checker settles while simplifying was reported as "no answer" and is now proven, confirmed by the checker itself; the first `loop()` runs as `millis()` starts counting.
- **`arclang prove`: code written by hand proven to be a machine of the model.** A `correspondence` says how a sketch and a machine relate: the pin each input is read from, the pin each output is written to, the expression of the sketch that is each state (`"mode == 1 is in Heating"`), the time a state has been held (`"millis() - since is time in Rising"`), what always holds of the sketch's variables (`invariant`), and the period of one `loop()`. The proof (CBMC and Bitwuzla) has two parts: after `setup()` and one `loop()`, and after the machine's start and one step, the two correspond; and from any two states that correspond, one `loop()` and one step with the same inputs leave two that correspond. Both hold: the sketch and the machine write the same outputs on every run, for ever. One fails: the proof is refuted, and the lines of the correspondence that do not hold after it are named, as is a pin the sketch reads or writes that the correspondence does not name. A `loop()` whose `delay()`s do not add up to the period is refuted too, a variable of the machine no line speaks of is named under the answer, and `int: 16` proves the sketch for a board whose `int` has 16 bits (the Uno), where a product can overflow that does not on 32. No answer in the time given is said as such, never as a proof. First for the C subset of the Arduino language (`digitalRead`, `analogRead`, `digitalWrite`, `millis`, `delay`, `pinMode`); three sketches are proven in the tests (a thermostat, a lamp toggled by a button, a debounced button) and each is refuted once its model, its code or its table is made wrong. The declaration goes through SysML v2 and back (`#Correspondence`).
- **`arclang drift --prove`: two codes proven to do the same, or the state and the inputs that tell them apart.** One step of the C as built and one step of the model's C are run from any state with any inputs, and every field of the state and of the outputs is compared: CBMC translates the two programs to one formula, Bitwuzla decides it. A code rewritten by hand that does the same is proven equivalent, whatever its text; a change of behaviour comes with a counterexample; a time limit reached is said as neither. The tools are in a new image, `tools/embedded/formal`.
- **The VHDL is proven as the C is.** `arclang recover <c> --hdl <dir> --check` reads the machines in the C, sizes those the logic computes from its register maps, and proves the logic by generating it again: the recovered model must generate every file of the logic (the VHDL, its wrapper, the register map, the driver, the fixed-point C) as it was read. The register map (`<block>_regs.json`) now says, for each variable, the range its word was sized for, where that range comes from and its bits: without them the logic could not be generated again. The three examples that generate VHDL are proven, C and logic. Because the register map is part of what a cached logic verdict depends on, the cached HDL and SoC verdicts are stale once.
- **`arclang drift`: the code as built against the model.** It reads the machines back from the C as built and from the C the model generates, the same way, and compares them: a guard, an initial value, the statement of an equation, the time or the target of a transition changed in the code is said in the terms of the model, with its line. Lines of the code that its machines do not explain (a helper edited by hand, a comment that no longer says what its statement does) are listed too. Every other file the model generates is compared too, line by line with the file as built: the I/O interface, the glue of the bindings and the host files, and with `--hdl <dir>` the VHDL, its register map, its driver and its fixed-point C. Every line found is listed. The command fails on a difference; `--json` gives the findings. See `docs/reverse-engineering.md`.
- **Reverse engineering, first step: `arclang recover`.** It reads the C the compiler generates for a model's state machines and gives the machines back as ArcLang: the states, where each machine starts, the ends, the guard and the timing of each transition, the initial values and the wiring are read in the statements; the names, the units and the text of the equations and actions in the generator's comments. `--check` proves it: the recovered model must generate, line for line, the C it was read from, so a comment that does not say what the code does, or a hand edit, is found with its line. The regions of a machine or of a state come back with their states and where each starts (their names are not in the code), and so do the transitions through pseudo-states: the branches of a choice or of a junction with their guards, the targets of a fork, the sources of a join, an entry by history, a terminate. The 27 examples that generate C are all recovered and proven, the power window and the in-flight entertainment model imported from Capella among them. See `docs/reverse-engineering.md`.
- Fixed: a value written in the unit of its variable went through the SI unit and back, which could move its last digit: `const off_below: Real [km/h] = 125 km/h` was `124.99999999999999` in the model's run and in the generated C and VHDL. It is the value written. The cached SIL and HDL verdicts of a machine with such a value are stale once (its generated code changes).
- **The diagram of a state machine shows what the machine runs.** A machine with regions was drawn flat, with one start; its pseudo-states were drawn as ordinary states, and a timed transition had no label. Each region is now a dashed frame with its name and its own start, a composite state shows where it starts, a choice is a diamond, a fork or a join a bar, a history a ring marked H or H*, an entry or exit point a ring, a terminate a cross, and a timed transition reads `after 200 ms`. The palette of the diagram has a tool for each (Region, Choice, Junction, Fork, Join, History, Deep history, Entry point, Exit point, Terminate), and a state can be declared in the selected region.
- Fixed: an edit from the views could not add a state or a transition inside a region ("it would change 2 places of the model"): what a region declares is listed twice in the syntax tree, and one declaration counted as two changes. The SysML v2 records served for a model said that a value given in a trace's annotation (`@Trace { rationale = "…"; }`) declared a feature named `rationale`; it redefines the one of the definition, as the OMG pilot implementation reads it (the workflow that compares the two had been failing since the annotation was introduced).
- **An export writes what its format says.** `arclang export -f yaml` wrote JSON; it writes YAML, of the model `-f json` writes. `arclang export -f xml` wrote an XML that called itself a Capella project, with texts not escaped (a `<` or a `"` in a description made a file no XML reader opens); it is ArcLang's own XML, escaped, and says it is not a Capella project. `arclang build --target capella` wrote that same XML into a `.capella` file Capella could not open; it writes the Capella project `arclang export -f capella` writes (`.capella`, `.aird`, `.afm`), and `--target xml` writes the XML.
- Fixed: in the MATLAB script of the Simulink connector, a quote in a description, a guard or an action ended the MATLAB text and what followed was run as statements; a quote is doubled and a line break is a space. The PlantUML import took any line holding `start` or `stop` (a component named "Starter motor") as an activity keyword and dropped it, read `[A] --> [B]` as a component and no relation, and did not read dotted arrows. `arclang trace --from/--to` without `--review` ignored both; they now keep the traces of those ends. `--config` and `build --incremental` never had an effect: they are still accepted, and the run says so.
- **The views follow the verdicts a terminal writes.** The gate, the requirements and the tables were computed once per version of the text: after `arclang verify`, `arclang sil` or `arclang hdl` in a terminal they kept the verdicts of before until the next keystroke. They are computed again when the verdicts beside the model change.
- **The assistant does not replace a file of yours before you have seen the change.** With `arclang.ai.applyDirectly` on, a change that wrote a file next to the model (a Modelica package, a CSV) over one already there was written at once; it now waits for **Apply**, and the chat says which file it replaces.
- **A model comes back whole from its own SysML v2 export.** `arclang export -f sys-ml` then `arclang import -f sysml` gave back 80 % of the elements of the examples, and the export of seven of them was refused on import (every model with a case that executes). It now gives back every element and every relationship of the 38 examples, with what they compute and what they prove: a state machine's variables and equations, a block without states, the actions of states, a transition's trigger, guard, action and timing, the regions of a machine (`state … parallel`, each region a `#Region` state), a case's `execute:`; the `io_binding`, `twin` and `rule` declarations, which SysML has no notion of, as `#IoBinding`, `#Twin` and `#Rule` parts of a package `Extensions` (without them a case no longer compiled, a twin was no longer followed, a rule no longer blocked the gate); what a trace says besides its ends (`rationale`, `reviewed`) as `@Trace { … }` in the body of its statement; a function's `realizes`, a requirement's name beside its id and the configurations it applies to, stakeholders, the attributes of EPBS items, a data type's base and unit, and a constraint's `sum(chain, attribute)` as `NumericalFunctions::sum((…))` (it came back as the sum of the chain's members of the day). Some values still do not come back: a component port's `interface` and `protocol`, the data type of a function port and of a functional exchange, the primitive type of a class field (`uint8` comes back as `Integer`), the `partition` of a deployment, the label of an operational exchange. On the 50 examples that compile, `arclang check` and `arclang gate` say the same of the model read back as of the original (line numbers apart), but for four archive models in the legacy syntax: a `connection` of a physical architecture comes back as a physical exchange, of which the gate then asks its ICD, and an id written twice comes back once. The OMG pilot implementation accepts the export of every example.
- **A reviewed link stays reviewed when only the spelling of a unit changes.** The fingerprint behind a suspect link took each quantity with its unit as written, so `85 %` rewritten `85 percent`, or `20 °C` read back as `293.15 K`, made every link of the element suspect, a blocker of the gate. A quantity now counts by its dimension and its value. The `reviewed:` marks already written stay valid while the element is written as it was; `arclang trace --review` writes the new ones.
- Fixed: the SysML v2 export of a requirement with a `subject:` and a `satisfy` was refused by the OMG pilot implementation ("Cannot override a binding feature value"); the subject is exported as `subject default = …;`. A transition written in a composite state was exported twice. An exchange with a function at one end came back as a component exchange. A quantity was exported rounded to nine decimals of its unit, so `0.1234567891234 s` lost digits and a value below a billionth of its unit went out as 0; it is written with its fifteen digits. On import, a string is read as an ArcLang block (`execute`, `simulate`, `data`) only when it is one balanced block and nothing after it.
- **The MCP server keeps to its workspace.** An agent gives the server the paths it reads and writes, and what the agent read (a model received from someone, a document, a web page) can ask it for any path. A path that leads outside the workspace (`ARCLANG_WORKSPACE`), `..` and links followed, is now refused, for reading and for writing. The extension starts the server on the folders that are open (the first is the workspace; without a folder, any path as before). **In another client, a tool given a path outside `ARCLANG_WORKSPACE` now answers that it is outside the workspace: name the other directories in `ARCLANG_MCP_ROOTS`** (separated like `PATH`), or `ARCLANG_MCP_ROOTS=*` for any path.
- **A model simulated in Docker runs without a network.** A model's Modelica can run commands where it is simulated, and a model can come from someone else. The container that runs it (`arclang verify`, `arclang twin`, the drawing of a Modelica class, the plant of a case in the loop) now starts with no network and no way to gain privileges, and reads the library volume without writing it; the Modelica Standard Library is installed by a separate container that runs no file of the model. Nothing changes for a model that only computes. **A model whose simulation fetches something from the network sets `ARCLANG_OMC_NETWORK=on`.** A local `omc` is not confined.
- **`arclang serve` without a token answers only this machine.** It listens on the loopback interface, but a web page could still read the served models through your browser by pointing its own name at your machine (DNS rebinding). Without a token or users, a request that names another host than `localhost`, `127.0.0.1` or `[::1]` now gets 403. With a token or users, nothing changes: declare one to serve it under another name, behind a proxy for instance.
- **The credentials of a live twin go only where you said.** The address of a twin's live data is written in the model; the user, password or token come from the environment (`ARCLANG_MQTT_*`, `ARCLANG_OPCUA_*`, `ARCLANG_KAFKA_*`, `ARCLANG_HTTP_TOKEN`). They were sent to whatever address the model named, so a model received from someone else could collect them. They now go only to this machine, or to a host named in `ARCLANG_TWIN_HOSTS` (`plc.plant.example`, `*.plant.example`, or `*` for any host, as before); otherwise `arclang twin --live` stops before it connects and names the variable to set. **If you follow a remote broker or API with credentials, set `ARCLANG_TWIN_HOSTS`.** A twin that connects without credentials is unchanged.

## 4.12.0

- The compiler: `arclang cosim` runs the executed cases as a standard FMI co-simulation in OMSimulator, OpenModelica's FMI and SSP master. The behavior's FMU, the plant's FMU (OpenModelica's, or the one the case gives) and the case's inputs are connected in an SSP package (`--keep` keeps `cosim.ssp`), and the run is judged as `sil` judges the C. With a plant, OMSimulator gives the plant the controller's outputs a period late, and the run is compared with the model's loop held the same way. ArcLang Studio now holds OMSimulator, and the command runs there when this computer has none. See docs/cosimulation.md.
- Fixed in `export -f fmu`: an `in` variable read from another machine (`from "M".y`) was an FMU input, set from outside and reported as set; it is now an output, the value the FMU computes. A model with a data-flow block no longer fails to compile as an FMU under `-Werror` (unused `first`).
- **ArcLang Studio** (docs/studio.md): one image, `ghcr.io/mbaroudi/arclang-studio`, published for amd64 and arm64 at each release.
