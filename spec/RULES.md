# ArcLang validation rules

What the compiler checks, as `arclang check --lint --json` reports it: each finding names its rule.

| Rule | Severity | Title | Meaning | How to answer |
|---|---|---|---|---|
| `syntax.unmodeled` | warning | Block not represented in the model | A block the parser accepts but the compiled model does not hold (a `dataflow`, for instance): its contents are ignored. | Model the content with constructs the metamodel holds, or remove the block. |
| `syntax.attribute-not-stored` | warning | Attribute not stored | An attribute written on a construct that does not keep it: it is read and dropped. | Move the information to an attribute the kind declares (see `arclang metamodel`), or remove it. |
| `metamodel.type` | error (gate blocker) | Typed attribute violated | A declared attribute does not fit its type: a quantity of the wrong dimension, an unknown enumeration value, a list where one value is expected. The production gate blocks on it. | Write a value of the declared type; `arclang metamodel` lists the type and the accepted values. |
| `metamodel.unit` | warning | Quantity without a unit | A bare number where the metamodel expects a quantity: the unit is assumed, the model should state it. | Write the unit with the number: `latency: 25 ms`. |
| `metamodel.reference` | warning | Reference to an element of another kind | A reference attribute names an element whose kind is not the one expected there. | Point the attribute at an element of the expected kind. |
| `identity.duplicate` | error (gate blocker) | Two elements share one identity | Two declarations resolve to the same id: traces and exchanges could not tell them apart. | Give one of them an explicit, unique `id`. |
| `spatial.length` | error (gate blocker) | Link shorter than the ground it covers | A physical link's `length` is shorter than its `route`, or than the distance between its located ends: the medium cannot be that short. | Correct the `length`, the `route` or the `location` of an end. |
| `spatial.max-length` | error (gate blocker) | Link beyond its maximum length | A physical link is longer than its `max_length` (a cable or bus limit): by its length, its route or the distance between its ends. | Shorten the route, move an end, or choose a medium that reaches that far. |
| `spatial.latency` | error (gate blocker) | Latency faster than light | A physical link's `latency` is shorter than the time light takes to cover its length: no medium carries a signal that fast. | Correct the `latency` or the length of the link. |
| `constraint.violated` | warning | Constraint violated | A declared `constraint` compares as false on the model's values. The production gate blocks on it. | Change the values the constraint compares, or the constraint, so that the model holds what it claims. |
| `trace.requirement` | warning | Requirement without a trace | No element satisfies, refines or verifies the requirement, in either direction: it is not covered. | Declare `trace "<element>" satisfies "<requirement>"`, or a test case that `verifies:` it. |
| `trace.component` | warning | Component without a trace | No trace names the component: nothing says what it realizes or satisfies. | Declare what the component satisfies or realizes with a `trace`. |
| `trace.suspect` | warning | Suspect trace | A trace reviewed against its two ends (`reviewed:`), one of which changed since: what it claims may no longer hold. The production gate blocks on it. | Check that the trace still holds (or correct it), then mark it reviewed: `arclang trace <model> --review --from <a> --to <b>`. |
| `rule.user` | warning | Rule of the model not held | An element does not hold a `rule` the model declares (`kind`, `where`, `require`). A rule of severity blocker stops the production gate. | Give the element what the rule requires, or change the rule. |
| `method.layer-order` | info | Layer without the one it refines | Arcadia builds each level on the previous one: a physical architecture realizes a logical one, which allocates system functions, which answer operational needs. | Add the missing level, or keep the model as a single-level study if that is what it is. |
| `method.component-functions` | info | Logical component without a function | Arcadia expects a logical component to realize behavior: at least one function is allocated to it. | Declare the functions the component performs inside it. |
| `method.exchange-transport` | info | Exchange between nodes without a physical link | A behavioral exchange between components deployed on different nodes must be carried by a physical link or exchange. | Declare the physical link (or physical exchange) between the two nodes. |
| `cesam.role` | warning | CESAM relation to a state of the wrong role | A technical configuration `realizes:` something other than a functional mode, a mode or configuration is available `during:` something other than a lifecycle phase, or a `context:` is written on a state that is no lifecycle phase. | Point the relation at a state of the expected machine (`kind: functional_modes`, `kind: lifecycle`), or give the machine the `kind:` it has. |
| `cesam.view-empty` | info | CESAM view not modelled | A cell of the CESAM grid (a vision seen through one aspect) holds nothing: that view of the system is not described yet. `arclang table --kind cesam_grid` shows the grid. | Model the view; the advisory names the Capella diagrams that draw it. |
| `cesam.stakeholder-need` | info | Stakeholder without a need | CESAM's stakeholder analysis gives every stakeholder its needs: here no concern names the stakeholder in `stakeholders:`. | Declare the stakeholder's concerns (`concern "..." { stakeholders: ["<stakeholder>"] }`), or remove the stakeholder. |
| `cesam.need-stakeholder` | info | Need without a stakeholder | A concern names no stakeholder although the model declares stakeholders: whose need it is is not said. | Write `stakeholders: [...]` on the concern. |
| `cesam.need-requirement` | info | Need framed by no requirement | No requirement frames the concern: the need is not turned into a stakeholder requirement. | Write `frames: ["<concern>"]` on the requirements that answer it. |
| `cesam.mission-use-case` | info | Mission without a use case | CESAM decomposes each mission into use cases (capabilities): no capability names this mission in `mission:`. | Declare the capabilities contributing to the mission, with `mission:`. |
| `cesam.use-case-scenario` | info | Use case without a scenario | CESAM illustrates each use case by operational scenarios: no scenario nor functional chain names this capability in `capability:`. | Write a scenario of the use case and give it `capability:`. |
| `cesam.lifecycle-context` | info | Lifecycle phase without an operational context | Each lifecycle phase has its operational context: the actors, systems and stakeholders around the system during it. | Write `context: [...]` on the phase. |
| `cesam.mode-configuration` | info | Functional mode realized by no technical configuration | The model has technical configurations, and none `realizes:` this functional mode: the mode has no concrete realization. | Write `realizes: ["<machine>.<mode>"]` on the configuration that provides the mode. |
| `cesam.requirement-vision` | info | Requirement without a CESAM vision | Nothing says whether the requirement is a stakeholder, a functional or a technical requirement: no block subtype, no `vision:`, nothing satisfying it. | Declare it in `requirements stakeholder|functional|technical`, write `vision:`, or trace what satisfies it. |
| `method.other` | info | Methodology advisory | An Arcadia advisory the catalog does not classify further. | Read the advisory. |
| `compile.other` | warning | Compiler warning | A warning the catalog does not classify further. | Read the warning. |

The production gate (`arclang gate`) reports its own findings, each named after its check: `requirements.presence`, `requirements.satisfaction`, `requirements.verification`, `verification.dangling`, `safety.hara`, `safety.asil`, `safety.dal`, `safety.mitigation`, `timing.latency`, `timing.budget`, `timing.units`, `icd.completeness`, `constraints.violated`, `metamodel.types`, `methodology`, `traceability.suspect`; a rule of the model reports under `rule.<its id>` (a blocker or a warning, as it says), and one that cannot hold under `rule.invalid`.
